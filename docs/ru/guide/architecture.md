# Архитектура

```
crew/
├── apps/
│   ├── server/        Hono — REST + WebSocket, раздаёт веб-интерфейс
│   └── web/           React 19 + Vite + Tailwind v4
├── packages/
│   ├── core/          Рантайм агентов, LLM-провайдеры, инструменты, промпт, воркер
│   ├── memory/        SQLite: агенты, сообщения, память (FTS5 + векторы), задачи
│   └── channels/      Telegram (grammY)
├── cli/               `crew` — публикуется как @vefimov/crew
├── docs/              Этот сайт (VitePress)
└── docker/
```

## Потоки данных

```
 Веб ──────┐
 CLI ──────┼──▶ Рантайм Crew ──▶ Провайдер (Ollama / OpenAI-совместимый)
 Telegram ─┘        │  ▲
                    ▼  │ инструменты: remember · recall · list/read/write files
                 SQLite (один файл)
                    │
                    ▼
             Очередь задач ──▶ извлечение памяти, догенерация эмбеддингов
```

## Почему так

- **Никаких нативных зависимостей.** `node:sqlite` встроен в Node 22, поэтому `npx` работает везде без компиляции.
- **Один файл состояния.** Агенты, чаты, память, векторы, настройки и очередь задач — в `~/.crew/crew.db` (режим WAL).
- **Гибридная память без векторной БД.** FTS5 + косинус перебором — с запасом на тысячи воспоминаний на агента и ноль дополнительных сервисов.
- **Независимость от провайдера.** Маленький интерфейс `Provider` (`chat`, `embed`, `models`, `ping`) со стримингом и tool calls. Адаптеры Ollama и OpenAI — по ~150 строк.
- **Всё через события.** Рантайм — это `EventEmitter`, сервер просто пересылает события в WebSocket, поэтому любой клиент видит всех агентов вживую.
- **Ходы по очереди.** Каждый агент обрабатывает один ход за раз, из какого бы канала ни пришло сообщение.
