# Архітектура

```
crew/
├── apps/
│   ├── server/        Hono — REST + WebSocket, роздає веб-інтерфейс
│   └── web/           React 19 + Vite + Tailwind v4
├── packages/
│   ├── core/          Рантайм агентів, LLM-провайдери, інструменти, промпт, воркер
│   ├── memory/        SQLite: агенти, повідомлення, пам'ять (FTS5 + вектори), задачі
│   └── channels/      Telegram (grammY)
├── cli/               `crew` — публікується як @vefimov/crew
├── docs/              Цей сайт (VitePress)
└── docker/
```

## Потоки даних

```
 Веб ──────┐
 CLI ──────┼──▶ Рантайм Crew ──▶ Провайдер (Ollama / OpenAI-сумісний)
 Telegram ─┘        │  ▲
                    ▼  │ інструменти: remember · recall · list/read/write files
                 SQLite (один файл)
                    │
                    ▼
             Черга задач ──▶ витягування пам'яті, догенерація ембедингів
```

## Чому так

- **Жодних нативних залежностей.** `node:sqlite` вбудований у Node 22, тому `npx` працює всюди без компіляції.
- **Один файл стану.** Агенти, чати, пам'ять, вектори, налаштування й черга задач — у `~/.crew/crew.db` (режим WAL).
- **Гібридна пам'ять без векторної БД.** FTS5 + косинус перебором — із запасом на тисячі спогадів на агента й нуль додаткових сервісів.
- **Незалежність від провайдера.** Маленький інтерфейс `Provider` (`chat`, `embed`, `models`, `ping`) зі стримінгом і tool calls. Адаптери Ollama та OpenAI — по ~150 рядків.
- **Усе через події.** Рантайм — це `EventEmitter`, сервер просто пересилає події у WebSocket, тому будь-який клієнт бачить усіх агентів наживо.
- **Ходи по черзі.** Кожен агент обробляє один хід за раз, з якого б каналу не прийшло повідомлення.
